## 0. 三条最重要的判断

### 判断一：lquant 的护城河是「A 股制度正确性 + 数据工程质量 + 交叉验证纪律」，不要为「引入成熟框架」而放弃

- A 组核查 13 个综合平台：**11 个对 A 股涨跌停 / T+1 没有任何内置证据**；只有 Hikyuu（部分，ST 5% 明确未实现）与 RQAlpha（最全）达到可依赖完整度（[A 报告](A-综合量化平台.md) §4）。
- 因子/组合组核查：`alphalens` 原版**已归档**，且默认 `filter_zscore=20` **自带前视偏差**（其自己 docstring 承认）；Alpha101 主流 Python 参考实现的 `rank()/scale()` 用了 pandas 默认 `axis=0`，**实际在时间轴排名而非截面**，污染面极广（[B 报告](B-因子与组合优化.md) §B.4）。
- 中文生态组核查：**没有找到有规模的「聚宽策略语义迁移」开源项目**——star 最高的 `easytrader`(10k+) 做的是交易执行桥接而非语义迁移。**这反证 `research/dialect/` 是一块罕见的自建差异化能力**（[E 报告](E-中文生态项目.md) §5）。
- 结论：`docs/BACKTEST_ENGINES.md` 的选型结论（自研引擎为唯一执行真源）被本次调研**反向证实**；vectorbt 式纯向量化无法表达 T+1/涨跌停的路径依赖，且其限价单能力在闭源 PRO 里（[A 报告](A-综合量化平台.md) §5）。

### 判断二：当前最大的短板不是功能，是数据资产与「声明的能力 ≠ 湖里的数据」

本次对 live 库/湖的只读实测（父 agent）：

| 事实 | 证据 |
|---|---|
| **2025 年日线整年缺失** | `data/parquet/daily/` 只有 `year=2021..2024,2026` 有 `part-0.parquet`；`year=2025/` 只剩 `part-0.parquet.bak-demo` 与 `.lock` |
| 2021–2023 只有约 1000 只标的 | 2021: 1,046 / 2022: 1,086 / 2023: 1,109；而 2024: 5,073 / 2026: 7,247 |
| **`security` 主表只有 3 行** | DuckDB `security` = 3（stock 2 + etf 1），退市 0 行 |
| **退市股在日线湖里一行都没有** | `docs/BACKTEST_BASELINE_E2E.md:161`：`security` 有 339 条 `delist_date`，在日线湖出现过的 = **0** → 幸存者偏差**依旧存在** |
| `adj_factor` / `minute_bar` 表 0 行 | DuckDB 实测 |
| `financial_pit` 77,446,911 行 | 唯一真正厚的数据资产 |

> 结论：**回填数据 > 补任何功能**。任何新因子、新模型、新优化器，都跑在这份有整年缺口与幸存者偏差的湖上。

### 判断三：值得借鉴的东西集中在四类，而不是「更多算法」

1. **数据完整性的门禁纪律**（水位/覆盖率门禁、稀疏 tip、契约探针、源级单飞锁、复权 fail-loud）
2. **A 股事件驱动数据面**（解禁 / 业绩预告 / 两融 / 大宗 / 股东户数 / 分红回购 / 宏观 / 筹码）
3. **统计纪律**（丢样账、zero_aware 分箱、CVaR/CDaR、purged CV、标签可交易屏蔽）
4. **风控与执行**（事前校验器链、费用区间版本化、交割队列、Regime/波动率目标）

## 2. 借鉴清单

> 每条给出：**来源 / 机制 / 为什么值得 / lquant 现状（已核对） / 集成点 / 成本**。

### P0 — 不做则「结论不可信」

#### P0-1 日线/分区完整性门禁 + 稀疏 tip 检测
- **来源**：CNEquity `meta/state`（覆盖率 ≥70% 才算当日完整）；C 报告 §Top1/2
- **机制**：写入路径上按「交易日 × 应有标的数」算覆盖率，低于阈值**不注册当日 `data_version`** 并落 `data_quality_issue`；对 `end=today` 的部分写入单独检测（水位新鲜但覆盖率断崖）
- **lquant 现状（已核对）**：有 `data/quality/coverage.py::scan_coverage`（**事后**扫描整日缺失/标的级稀疏）、`data/store/integrity.py::check_partition_continuity`、`data/ingest/checkpoint.py`（symbol 级覆盖区间语义）、`data/ingest/daily.py:198-202`（`empty_response` 显式标记，未跑不标 done）。**缺的是日期级、阈值化的门禁**：现在缺口能被发现，但不会阻断，也不会阻止版本推进。更具体一点，`daily.py:444-451` 是**先 `lineage.register` 再 `gate_daily`** —— 门禁 fatal 时会出现「已登记版本但零行入湖」，而注册时只记 `row_count`，**没有任何「当日应有多少标的」的完整性概念**
- **集成点**：`data/quality/coverage.py`（加 `day_completeness()`）、`data/ingest/daily.py`（写后门禁）、`data/lineage.py::register`
- **验收**：构造「5000 只只成功 1000 只」的批次 → 断言该日不注册 `data_version` 且产生一条 issue
- **成本**：低（1–2 天）

#### P0-2 复权：查询期派生 + `strict_adj` fail-loud
- **来源**：free-stockdb（查询时计算）、CNEquity ADR；C 报告 §Top4/5
- **机制**：只持久化**不复权价 + 复权因子**，qfq 在查询期按窗口 anchor 派生（`f_qfq(t)=hfq(t)/hfq(T)`）；缺因子**报错**而不是静默 `factor=1.0`
- **lquant 现状（已核对）**：**已经是对的方向**——BaoStock 只取 `adjustflag="3"` 原始价，复权读取时用 `adj_factor` 动态算。差距在 fail-loud：仓库存在 `_safe_std` 兜底 1.0 这类静默回退的同类模式（`docs/research/00-borrow-and-port-plan.md:60`）
- **集成点**：`data/quality/adjustment.py`、`factors/preprocess/standardize.py`
- **成本**：低

#### P0-3 回填数据资产（不是竞品 borrow，但优先级高于一切）
- **做什么**：① 从 `data/parquet/daily.bak-demo-20260918-144538/year=2025/` 恢复 2025 日线（审计已确认可恢复）；② 回填退市标的（含退市前 N 年）日线；③ 重建 `security` 主表
- **依据**：本报告判断二 + `docs/DATA_ROBUSTNESS_AUDIT-2026-10-03.md` + `docs/BACKTEST_BASELINE_E2E.md:161`
- **验收**：2025 有 `part-0.parquet`；退市股在日线湖可查到；长回测的股票池包含已退市标的

#### P0-4 北向资金口径核对或重建
- **来源**：C 报告 §不要借鉴（[新华财经 2024-08-19](https://www.cnfin.com/yw-lb/detail/20240819/4090757_1.html)）
- **事实**：2024-05-13 取消盘中实时；**2024-08-19 起不再公布「净买入」**，只公布成交总额/笔数、前十大成交活跃证券、季度末单只持股。**任何仍展示「北向实时净流入」的模块都是失效或伪造**
- **lquant 现状（已核对）**：`market/collectors/money_flow.py:99-142` 仍在用东财 `kamt/get` 解析 `hk2sh/hk2sz` 的「净买额」；`northbound_flow` 表有 16 行真实数据；`market/schema.py:142` 注释已写「2024-08 后仅盘后公布总额」，但列名与看板口径**仍叫净流入**。这是**静默口径错误**的典型形态
- **要做**：核对 `f51/f52` 现在到底返回什么；若已不是净买额 → 改列名/改看板/改用「前十大活跃成交股 + 季度持股 + 龙虎榜沪股通·深股通专用席位」
- **集成点**：`market/collectors/money_flow.py`、`market/schema.py`、`server/api/market.py`、前端 dashboard
- **成本**：低

#### P0-5 源级单飞锁（并发会话互斥）
- **来源**：CNEquity `RunLock("baostock")`；C 报告 §Top9
- **机制**：限流管**速率**，单飞锁管**并发会话**——两者正交。原文：「rate-limit alone 不能阻止 N 个会话同时 login()」
- **lquant 现状**：有 `data/ratelimit.py::TokenBucket`、DuckDB 单写者锁、`data/watchdog.py` 子进程超时；**无源级并发锁**。BaoStock 黑名单错误码 `10001011`（触发条件：日请求 >5 万 / **并发连接** / 扫太快）正是这个风险
- **集成点**：`data/ratelimit.py` + `data/providers/_engine.py`
- **验收**：两个 worker 同时拉同一源 → 断言互斥
- **成本**：低

#### P0-6 标签工程：可交易屏蔽 + 与执行口径一致
- **来源**：quant-ashare（父 agent 补漏，见 §3）、F 报告；行业经验「涨停/停牌/财报窗口不屏蔽会让回测 IC 系统性虚高 20–30%」（**该数字来自该项目自述，本仓未实测，按经验值看待**）
- **机制**：① 涨跌停/一字板/停牌/新股/ST/财报披露窗口/解禁窗口 做**样本屏蔽**（不是删数据，是 mask）；② 今收决策、次开入场 → label 用 `close[t+h]/open[t+1]`；③ 多 horizon + 波动率归一化 + 截面排名
- **lquant 现状（已核对）**：`data/quality/tradability.py::flag_tradability` **已经打了 ST/新股/停牌位掩码**，但 `research/ml/dataset.py::build_dataset` **完全不消费 `quality_flags`**（全仓 grep：`research/ml/` 只在 `panel.py:97` 提到该列名）；`DatasetConfig.price_col` 默认 `"close"`（`dataset.py:27`），而引擎是「T 日收盘出信号 → T+1 开盘撮合」。→ **训练标签与执行口径不一致，且没有屏蔽**
- **集成点**：`research/ml/dataset.py`（mask 参数 + `entry_price` 口径）、`factors/evaluate/returns.py`（提供 executable 口径）、报告契约标注
- **注意**：因子评价的 IC 应保持 close→close 的**可比口径**，只在 ML 训练/组合构建时用 executable 口径，两者都要在报告里写明
- **成本**：低-中；**价值：高**

#### P0-7 Agent 结论的证据可回溯（trace + 结构化契约 + withheld）
- **来源**：D 报告 §5 B1/B2/B3（Five Sins、TradingAgents、FinRobot、LLM_QUANT_FACTORY）
- **机制**：① 每次工具调用落 **name / 入参 / 出参摘要 / 起止时间 / as-of 数据时点 / 是否降级**；② 结论走 `AgentVerdict{ticker, as_of, direction, confidence, evidence[{source, as_of, quote}], abstain}` 结构化契约，**数字字段无 source/as_of 即拒收**；③ 历史时点取不到的数据返回 `unavailable`，**禁止静默用当前数据顶替**
- **lquant 现状（父 agent 实测，修正 D 报告一处不准）**：`ask_messages.tool_calls_json` **已经落库工具名与入参**（实测 36 条消息，形如 `[{"name":"market_overview","args":{}}]`，`agent/sessions.py:32`）——D 说「tool_call 不落库」不准确。真实缺口是：**工具返回内容、as-of 时点、降级标记不落库**；且没有结构化 verdict 与 withheld 语义
- **集成点**：`agent/sessions.py`、`agent/cli_agent.py`、`agent/schemas.py`、`agent/mcp_server.py` 工具契约
- **成本**：中

#### P0-8 费用/税按监管区间版本化 + 交割队列通用化
- **来源**：Hikyuu `TC_FixedA2015/2017/ETF`（[FixedA2017TradeCost.cpp](https://github.com/fasiondog/hikyuu/blob/master/hikyuu_cpp/hikyuu/trade_manage/imp/FixedA2017TradeCost.cpp)）、qteasy `cash/stock_delivery_queue`（A 报告 §Top1/3）
- **机制**：把费率表做成**按监管区间切换的版本化对象**；T+N 抽象成**交割队列状态机**（A 股即 `period=1`），避免制度特判散落各处
- **lquant 现状（已核对 `config/rules/cn_a_share.yaml`）**：
  - **印花税已是历史区间 + 买卖方向**（7 段区间，2008-09-19 起单边）→ **领先**
  - **过户费是单一常数**（`transfer_fee.rate: 0.00001`，注释「沪深过户费（双向）」）→ **未区间化、未分市场**。历史事实：2022-04-29 起沪深统一下调至 0.001%（双向）；此前沪市 0.002%；**深市 2015-08-01 前免收过户费**。因此 2022 年前、以及深市 2015-08 前的长回测，过户费口径是错的（**静默偏差**）
  - T+N 已有 per-instrument `sellable_after_days` 且按**交易日**算（D3 已修），但仍是「字段」而非「队列」
- **要做**：过户费补 `schedule`（区间 + 分市场）；经手费同理；T+N 收口成交割队列
- **集成点**：`backtest/rules/model.py::TaxSchedule`、`config/rules/cn_a_share.yaml`、`backtest/account.py`
- **成本**：低-中（lquant 已具备大部分语义，是**收口**而非新造）

### P1 — 把链路补完整

#### P1-2 涨停池 / 龙虎榜语义层 + 基于它们建因子
- **来源**：C 报告 §Top6/7；quant-ashare `factors/alpha_limit.py`(16 因子) / `seat_network.py`(13 因子)

## 3. 父 agent 补漏：quant-ashare（六路调研都未覆盖）

[wangpage/quant-ashare](https://github.com/wangpage/quant-ashare)（MIT，个人项目，「机构级 A 股研究框架」）。**必须带质量折扣看待**：自称 65 个数值测试 + 约 120 个冒烟测试，README 说「实装 12+ 暗门」，但它是单人项目、无同行验证。

**它值得看的原因**：它恰好把 lquant 的一批缺口逐个实现了一遍，且**诚实披露了自己的失败**：
- 早期版本宣称「夏普 1.86 / IR 1.21」，**修复 label leak 后 OOS IR 掉到 -0.13 ~ +0.2**；用真实数据复测发现反转族因子的「显著」是**重叠样本假象**（日频未来 5 日收益相邻重叠 4/5，t 值系统性虚高），换非重叠周频 + 扣 sqrt 冲击成本后 t 塌到 0.97，Top30 扣费后**跑输等权 55%/年**
- 结论：「公开因子 + LightGBM + 月频选股，真实 OOS 夏普天花板 0.5–1.0」

**给 lquant 的两点直接价值**：
1. **它的 15 条「暗门」清单可以直接当缺口 checklist**：标签工程 / 涨跌停停牌屏蔽 / Level2 微结构 (OIR/VPIN/Kyle's λ) / Almgren-Chriss / Barra CNE5 / 因子衰减监控 / 组合优化 / 事件屏蔽 / 数据清洗 / 主题投资识别 / Regime 自适应 / 资金流因子 / 涨停连板因子 16 个 / 龙虎榜席位因子 13 个 / 执行时段避让。上面 P0-6、P1-1、P1-2、P1-3、P1-5、P2-5~P2-8 都来自这张表
2. **它的「诚实披露」正是 lquant 已经在做的事**：lquant 的 `evaluate/ic.py` 有 Newey-West `t_stat_nw`、`docs/FACTOR_VALIDATION.md` 有方法学——**lquant 在统计纪律上领先于它**，不必外借；但它的失败案例可以作为「为什么必须有 NW-t 与非重叠样本」的内部教材

- **backtesting.py**：AGPL-3.0；**backtrader / Abupy**：GPL-3.0；**QuantMind**：AGPL-3.0（传染）
- **NOASSERTION**（许可不明，风险最高）：`czsc`、`TradingAgents-CN`、`akshare-proxy-patch`
- **无 License**（默认保留所有权利）：`Sequoia-X`、`MyTT`、`mootdx`、`efinance`

### 4.2 已失效 / 高风险依赖

### 4.3 算法/口径类（会被误当「行业标准」）
| 不要做 | 为什么 | 证据 |
|---|---|---|
| 引入 `alphalens` 作依赖 | 原版**已归档**；默认 `filter_zscore=20` **自带前视偏差**（其 docstring 自认）；纯 pandas 长表慢 | B §A.4 |
| 照抄 Alpha101/191 Python 参考实现 | `rank()/scale()` 用 pandas 默认 `axis=0`，**在时间轴排名而非截面**；Alpha57/38/27 转录错误；~20 条依赖未实现的 `IndNeutralize`；`as_matrix()` 已移除 | B §B.4 |
| 依赖任何开源 Barra 实现 | 无成熟项目（`Peimou/barra-risk-model` README 仅 3 行） | B §F.2 |
| **自研筹码分布** | 无 ground truth，通达信/同花顺/东财三家口径不一致。F 组源码实锤：集中度=前 5 bin 占比和**随 bins 与价格区间宽度变化、无量纲化、跨股票不可比**；衰减与新增量不自洽；**未处理复权**。→ **直接接 `stock_cyq_em`** | F §不必借鉴 |
| **自研 K 线形态识别** | 无权威定义不可证伪；step × 阈值组合上千 = 多重检验过拟合。F 组源码实锤：391 行 6 个检测器 **0 测试**、杯柄的 `max_cup_depth_pct` 是 **dead parameter**、只用 close 忽略 high/low、**无突破确认无量能确认**。→ 最多暴露 **ZigZag 原语**给 DSL，**不下「这是 W 底」的断言** | F §不必借鉴 |
| 缠论作**信号源** | 划分规则各家自定、无可证伪内容（czsc / chan.py / chanlun-pro 划分可能互不一致）。**只借它的分层工程**（P2-2） | E §Top2 + F |
| 把宏观指标按「数据期」对齐 | 9 月 CPI 在 10 月才公布 → 前视偏差。必须**发布日对齐 + 自建发布日历** | F §不必借鉴 |

### 4.4 LLM / Agent 类
| 不要做 | 为什么 | 证据 |
|---|---|---|
| 让 LLM 直接产出买卖/仓位并号称可回测 alpha | 前视污染 + 摩擦 + 研究者自由度三重混杂。复现净 Sharpe：TradingAgents 0.43→0.22、QuantAgent −0.96→−1.15，**均低于 buy-and-hold** | D §6.2/§4.1 |
| 用 cutoff 内窗口回测当证据 | 参数化记忆 + 检索污染两通道；声明的 cutoff 不可验证（164 篇论文仅 26.8% 提及前视） | D §7 |
| 把多智能体辩论当准确性来源 | 4 模型 × 9 基准 = 36 组配置，辩论胜率 **<20%**；加轮数不加分 | D §4.3 |
| **为「多智能体」引入重编排框架进主 venv** | FinRobot 自己换了三代框架（AutoGen→Agents SDK→PydanticAI）；与既有 ADR-11 一致 | D §7 |
| 爬问财（iwencai）做生产链路 | 无 PIT（返回当前结果）、列名由页面决定不可契约化 | D §2.E |
| 把截图/演示页当绩效证据 | LLM_QUANT_FACTORY 明令截图不进研究记忆 | D §7 |
| LLM 生成因子直接入库 | lquant **已有** G0 静态（含未来函数）→ G1 快筛 → G2 去重 → G3 复核 + `sqrt(2·ln n)` 校正；**保持，不要放松** | 源码 `factors/mining/gates.py` / `runner.py` |
