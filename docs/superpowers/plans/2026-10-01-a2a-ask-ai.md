### 2.3 缺口

**G1 · A2A 协议层完全缺失（本轮主体）**

全仓检索 `a2a / agent2agent / agent-card / agent_card` 无任何命中。缺：

- Agent Card 发现端点
- JSON-RPC `message/send` / `message/stream` 分发
- Task 生命周期与状态机（`submitted` / `working` / `completed` / `failed` / `canceled`）
- SSE 流式投递
- A2A 对象（`Task` / `Message` / `Part` / `Artifact` / `TaskStatusUpdateEvent` / `TaskArtifactUpdateEvent`）
- 现有 `AgentEvent` 是自定义 5 事件协议，与 A2A 对象模型**不一致**，需要一层显式映射

**G2 · 默认 provider 是 `mock`，不是内置 Claude Code**

证据：

- `src/lquant/core/config.py:48` → `provider: str = "mock"`
- `src/lquant/core/settings_store.py:35` → `SettingDef(default="mock", ...)`
- `config/app.yaml` **根本没有 `agent:` 段**，`agent.*` 全部走代码默认值

后果：默认部署下「问 AI」返回的是脚本化假回答，与「问 AI 就等于问 Claude Code」的口径不符。更糟的是 `mock` 会**用真实数据接口拼一段很像真的回答**（`agent/mock.py`），使用者不容易察觉后端不是 LLM。

**G3 · 模型接入不可配**

- `AgentConfig` 只有 `provider / claude_path / workspace_dir / timeout_seconds / skip_permissions`，**没有 `model` / base_url / token**
- `claude_code.py:187-199` 拼的 cmd 里**没有 `--model`**
- 子进程 env 是 `dict(os.environ)` 全量继承（`claude_code.py:50`）—— 所以 `ANTHROPIC_MODEL` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` **事实上能生效**，但：无配置项、无文档、无 `.env` 装载、无校验；换个人接手只能靠读源码猜
- 对第三方兼容网关（如走 `ANTHROPIC_BASE_URL` 的代理）没有任何说明

**G4 · `a-stock-data` skill 与工作区 CLAUDE.md 指引互斥**

- `workspace.py:21-25` 的 CLAUDE.md 写：「**MCP 工具** → **lquant CLI** → **临时 python 脚本**」——**没有提到 skill，也没有提到 HTTP API**
- `config/skills/a-stock-data/SKILL.md` 却说「通过 lquant 本地 HTTP API（默认 `http://localhost:8000`）查询」
- `claude_code.py:21-24` 的 `--append-system-prompt` 又只说「优先使用 lquant MCP 工具查询数据」

三份指引口径不同，agent 只能自己猜。另外 base URL 硬编码 `localhost:8000`，端口/主机变了即失效。

**G5 · MCP 工具面与 skill 能力不对齐**

MCP 只有 4 个工具（`get_quotes` / `get_daily` / `list_factors` / `get_factor_values`），而 skill 覆盖的**大盘概览 / 涨跌家数 / 板块 / 资金流 / 涨停池 / 龙虎榜 / 热榜 / 指数 / ETF 全部没有对应 MCP 工具**，只能绕 HTTP。

已核对端点真实存在（`server/api/market.py`）：`/overview` `/sectors` `/money-flow` `/limit-up` `/dragon-tiger` `/breadth` `/batch` `/snapshot` `/heat` `/index` `/collectors` `/collect-status`；`/api/etf/` 实际只有 `meta` / `by-symbol/{symbol}` / `correlation`（skill 里写的 `/api/etf/*` 是模糊表述，需要收紧）。

### 2.4 缺陷（顺带应在同一 PR 修掉）

**D1 · 单会话并发发消息互相踩（真实缺陷）**

`claude_code.py` 用 **session 单槽** 存运行时引用：

```python
self._tasks[sid] = asyncio.current_task()   # :161
self._procs[sid] = proc                     # :205
...
self._procs.pop(sid, None)                  # :277（finally，无归属校验）
```

而 `server/api/ask.py` 的发消息接口**没有任何并发守卫**。同一会话连发两条：第二条覆盖 `_tasks[sid]`，第一条的 task 引用丢失；随后 `/cancel` 只会取消第二条；任一条先结束就会把 `_procs[sid]` 提前 pop，另一条变成孤儿进程。前端还会看到两条回答的事件交错。

**D2 · `attach()` 失败会留下孤儿 `claude` 进程**

```python
proc = _Child(cmd, cwd=str(self._workspace))   # 子进程已启动
await proc.attach()                            # 这里抛 OSError
# except 分支只 raise，从未 terminate / waitpid
```

`attach()` 抛错时子进程已在跑且无人回收，`_run` 也没有 `finally` 兜底。

**D3 · A2A 会把本机代码执行面变成网络可达面（安全）**

`docs/SECURITY.md` 已声明：`agent.provider = claude_code` 时以 `--dangerously-skip-permissions` 拉起 CLI，**可任意读写本机**；且 `AgentConfig.skip_permissions` 默认 `True`。A2A 端点一旦暴露，等于把「谁能访问这个 API 谁就能在这台机器上执行代码」这件事从「本机进程」扩大到「网络」。方案里必须有显式收口（见 §4.8）。

**D4 · `main.py` CORS 只允许 `http://localhost:3000`**（`main.py:55`）

服务间 A2A 调用（无 `Origin` 头）不受影响，但浏览器侧跨源调 A2A 会被挡。需要显式决定策略。

**D5 · 未标记取消语义**

用户主动 `/cancel` 时 `send_message` 发的是 `event.type="error"`（`claude_code.py:165`），前端会把它当错误展示；落库消息也没有「已中断」标记。

**D6 · 命名碰撞（不必改，但要知道）**

仓库里有**两套「agent」**：

1. 问 AI：`src/lquant/agent/`（本方案目标）
2. 因子挖掘 Agent 注册表：`config/agents/*.yaml` + `src/lquant/factors/agents.py` + `lq agent list/show/test`，其中 `remote-miner.yaml` 已经有 `kind: external` + `transport: http|subprocess|mcp` + `endpoint`

两者互不相干。本方案**不动**挖掘注册表；但要注意 `transport` 枚举与 A2A 是同一语义空间，将来若要统一，`transport: a2a` 应加在挖掘侧而不是复用问 AI 侧。

## 3. 目标架构（lquant 作为 A2A 服务端）

```
                  ┌──────────────────────────────────────────┐
  外部 A2A 客户端 │  1. GET /.well-known/agent-card.json      │
  （其他 Agent /  │  2. POST /a2a  {"method":"message/send"}  │
   调度器 / 平台） │               或 "message/stream" (SSE)   │
                  └──────────────────┬───────────────────────┘
                                     ▼
                        server/api/a2a.py（新增）
                    ┌────────────────────────────────────┐
                    │ a2a/rpc.py    JSON-RPC 2.0 分发     │
                    │ a2a/card.py   Agent Card（skills 派生）│
                    │ a2a/executor.py 编排 + 生命周期      │
                    │ a2a/mapper.py AgentEvent ⇄ A2A 对象  │
                    │ a2a/tasks.py  Task 持久化            │
                    └────────────────┬───────────────────┘
                                     ▼
                        AgentService（不变）
                    ┌────────────────────────────────────┐
                    │ ClaudeCodeAgentService（内置）       │
                    │   posix_spawn claude -p ... --model  │
                    │   cwd = data/agent_workspace         │
                    └────────────────┬───────────────────┘
                                     ▼
                  Claude Code CLI ─┬─ MCP: lquant stdio（4→13 工具）
                                   ├─ skills: a-stock-data / factor-mining
                                   └─ 模型：ANTHROPIC_* / --model（原生配置）

  web /ask（保持不变）── /api/ask + WS（内部仍走 AgentService）
```

**关键设计决策：A2A 与 web 共用同一套事实源。**
A2A 的 `contextId` 直接映射为 `ask_sessions.id`，`taskId` 落在新表 `a2a_tasks`。这样：外部 Agent 通过 A2A 提的问题，会**出现在 `/ask` 页面**；反之亦然。WS 事件总线（`AskEventBus`）同时喂 WS 与 A2A 的 SSE，不重复实现。

## 4. 详细设计

### 4.1 A2A 数据模型（`agent/a2a/types.py`）

按 A2A 1.0 实现**够用的子集**（pydantic，camelCase 序列化）：

- `AgentCard`：`name` `description` `version` `supportedInterfaces[]` `capabilities` `defaultInputModes` `defaultOutputModes` `skills[]`（+ 可选 `provider` `documentationUrl`）
- `AgentInterface`：`url` `protocolBinding` `protocolVersion`
- `AgentCapabilities`：`streaming: true`、`pushNotifications: false`、`extendedAgentCard: false`
- `AgentSkill`：`id` `name` `description` `tags[]`
- `Message`：`messageId`（必填）`contextId` `taskId` `role`（`ROLE_USER`/`ROLE_AGENT`）`parts[]`
- `Part`：`text` / `data` / `url` 三选一（**只支持 `text`，`data` 仅内部用**）
- `Task`：`id`（必填）`contextId` `status` `artifacts[]` `history[]`
- `TaskStatus`：`state` `message`
- `TaskState`：`TASK_STATE_SUBMITTED` / `WORKING` / `COMPLETED` / `FAILED` / `CANCELED` / `INPUT_REQUIRED` / `REJECTED`
- `Artifact`：`artifactId`（必填）`name` `parts[]`
- `TaskStatusUpdateEvent`：`taskId` `contextId` `status` `final`
- `TaskArtifactUpdateEvent`：`taskId` `contextId` `artifact` `append` `lastChunk`

### 4.2 Agent Card（`agent/a2a/card.py`）

- 路径：**`GET /.well-known/agent-card.json`**（RFC 8615 规范位；A2A 0.3 起的标准位，1.0 沿用）
- 响应头：`Content-Type: application/json`、`Cache-Control: public, max-age=60`、`A2A-Version: 1.0`
- `skills[]` **从 `config/skills/*/SKILL.md` 的 frontmatter 派生**（`name` / `description` + tags 映射）—— 新增 skill 自动进 card，不用改代码
- 卡片内容先给两版：`a-stock-data`（A 股数据查询）与 `factor-mining`（因子挖掘评估）
- `supportedInterfaces[0]` = `{protocolBinding: "JSONRPC", protocolVersion: "1.0", url: "<base>/a2a"}`

### 4.3 事件映射（`agent/a2a/mapper.py`，纯函数，重点单测）

**出站（AgentEvent → A2A StreamResponse）**

| AgentEvent | A2A 帧 |
|---|---|
| 请求受理 | `{"task": {id, contextId, status:{state:"TASK_STATE_SUBMITTED"}, history:[msg]}}` |
| 首轮开工 | `{"statusUpdate": {taskId, contextId, status:{state:"TASK_STATE_WORKING"}, final:false}}` |
| `assistant_delta` | `{"artifactUpdate": {taskId, contextId, artifact:{artifactId, parts:[{text}]}, append:true, lastChunk:false}}` |
| `tool_call` | `{"statusUpdate": {… status:{state:"TASK_STATE_WORKING", message:{role:"ROLE_AGENT", parts:[{text:"正在调用 <name>"}]}}, final:false}}` + `metadata.tool={"name","args"}` |
| `tool_result` | 同 `working` 状态帧，`metadata.tool_result=summary` |
| `done` | 先 `artifactUpdate(lastChunk:true)`，再 `{"statusUpdate": {… status:{state:"TASK_STATE_COMPLETED"}, final:true}}` |
| `error` | `{"statusUpdate": {… status:{state:"TASK_STATE_FAILED", message:{parts:[{text}]}}, final:true}}` |
| 用户 cancel | `{"statusUpdate": {… status:{state:"TASK_STATE_CANCELED"}, final:true}}` |

**入站（A2A Message → prompt）**：拼接所有 `parts[].text`；无 `text` part 或全空白 → JSON-RPC `-32602`。

### 4.4 任务与上下文映射（`agent/a2a/tasks.py`）

复用 `data/ask.db`，新增表（`CREATE TABLE IF NOT EXISTS`，与现有 `_migrate` 风格一致）：

```sql
CREATE TABLE IF NOT EXISTS a2a_tasks (
    task_id    TEXT PRIMARY KEY,
    context_id TEXT NOT NULL,          -- = ask_sessions.id
    state      TEXT NOT NULL,
    message_id TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_a2a_tasks_ctx ON a2a_tasks(context_id, created_at);
```

规则：

- 请求不带 `contextId` → 新建 `ask_sessions`，以其 id 作为 `contextId`
- 请求带 `contextId` → 校验 session 存在，否则 `TaskNotFoundError`
- 每个 `message/send` 建一个新 `taskId`
- `tasks/get` / `tasks/cancel` 读写本表 + 复用手里的 `AgentService.cancel`

### 4.5 端点与传输（`server/api/a2a.py`）

| 路由 | 说明 |
|---|---|
| `GET /.well-known/agent-card.json` | Agent Card（**必须挂在无 `/api` 前缀处**，见 §5 接线说明） |
| `POST /a2a` | JSON-RPC 2.0 单端点；`Content-Type: application/json`；`A2A-Version: 1.0` 头 |

方法集（`rpc.py`）：

| 方法 | 行为 |
|---|---|
| `message/send` | 同步阻塞到终态，返回 `Task`；带 `returnImmediately: true` 时先返回 `working` 态 `Task` |
| `message/stream` | **SSE**（`text/event-stream`），按 §4.3 顺序投帧，终态后关流 |
| `tasks/get` | 查 Task 状态 |
| `tasks/cancel` | 取消（转 `AgentService.cancel`），未知 task → `TaskNotFoundError` |

兼容别名：同时接受 `SendMessage` / `SendStreamingMessage` / `GetTask` / `CancelTask`（不同实现的方法名拼写不一，见 A2A 1.0 各实现差异）。未知方法 → `-32601`。

错误码按 JSON-RPC + A2A 惯例：`-32700` 解析错、`-32600` 非法请求、`-32601` 方法不存在、`-32602` 参数非法、`-32603` 内部错；A2A 语义错误用 `error.data` 带 `TaskNotFoundError` / `ContentTypeNotSupportedError` / `UnsupportedOperationError`。

### 4.6 模型接入（只走 Claude Code 原生配置，不做平台配置 UI）

**改动**

1. `AgentConfig` 增两个字段（`core/config.py`）：

2. `claude_code.py`：`model` 非空时追加 `--model`；子进程 env 改为 `{**os.environ, **self._env}`，并**保证 `LQ_ROOT` / `PYTHONPATH` 一定透传**（MCP server 依赖）
3. `config/app.yaml` **新增 `agent:` 段**（现在完全没有）：

     model: ${LQ_AGENT_MODEL:}

### 4.8 安全边界（必须做，不是可选项）

1. **默认只绑回环**：沿用 `LQ_API_HOST=127.0.0.1`（`lquant.sh` 已有）；A2A 端点不额外开监听。
2. **可选 Bearer 鉴权**：新增 `LQ_A2A_TOKEN`。设置后所有 `POST /a2a` 必须带 `Authorization: Bearer <token>`，Card 里条件性声明 `securitySchemes`；未设置时保持本地单人无鉴权，但**启动时打 warning**（与 `service.py:70-77` 现有的 `_WARNED_PROVIDERS` 告警风格一致）。
3. **Card / README 明确写清**：A2A 端点 = 可执行本机代码的入口，等价于 shell 访问权。
4. **`docs/SECURITY.md` 增一节** A2A，与现有「三层收口」并列。
5. `message/send` 的 `history` 回显**只回文本 part**，不回 tool 原始参数（避免把内部路径/命令泄给调用方）。

## 8. 待你确认的决策点

| # | 决策 | 我的建议 |
|---|---|---|
| 1 | JSON-RPC 方法名：规范名 `message/send`+`message/stream`，还是 1.0 抽象名 `SendMessage`+`SendStreamingMessage` | **规范名为主 + 抽象名做别名兼容**（各实现拼写不一，别名成本极低） |
| 2 | Agent Card 版本形态：只声明 `supportedInterfaces[0]=JSONRPC@1.0`，还是同时声明 `HTTP+JSON` | **只声明 JSONRPC**（HTTP+JSON 是另一套路径后缀路由，YAGNI） |
| 3 | 鉴权：默认无 token（仅回环），还是强制 `LQ_A2A_TOKEN` | **默认无 token + 启动 warning**，与现有本地单人定位一致；token 作为可选加固 |
| 4 | `AgentConfig.provider` 默认值是否从 `mock` 改成 `claude_code` | **改**。否则「问 AI = 问 Claude Code」不成立；同时保留 `mock` 作为显式选择（测试与无 CLI 环境用），但要在 UI/日志里标明「当前是 mock，不是真 LLM」 |
| 5 | A2A `contextId` 与 web `ask_sessions` 是否共用一份存储 | **共用**（§3 的关键决策）。好处是双向可见；代价是 A2A 与 web 的会话列表混在一起 |
| 6 | 是否实现 `tasks/get` + `tasks/cancel` | **实现**。A2A 客户端普遍会调；不实现会让 `message/send` 的异步模式不可用 |
| 7 | `mock` provider 是否保留 | **保留**，但把默认改掉，并在回答里加显式标记（避免「假回答看起来像真的」） |
