## 一、结论

**引擎层（算得出来）基本完备；暴露层（拿得到）与契约层（说的和做的一致）不完备。**

| 维度 | 判定 | 依据 |
|---|---|---|
| 评价维度覆盖 | ✅ 完备 | IC/RankIC、分层、衰减、归因、换手、成本、超额、Top-N、事件式、滚动、分组 IC、评级、稳健性 —— 13 类全部有实现（`factors/evaluate/` 18 个模块） |
| 中性化 | ✅ 内核完备 | winsorize / standardize / neutralize(ols/ridge/lasso/industry_mean) / orthogonalize(symmetric/gs/pca)，PIT 行业 + 覆盖率上报 + log 市值（`covariates.py`） |
| DSL 算子 | ✅ 超额完成 | 34 个（方案目标 ~30） |
| 正确性地基 | 🟡 基本达标 | F1–F6 有实现有脚本；N1–N6 有测试但**未纳入 `validate_factor.py`**，且文档仍标记为「⏳ 未完成」（文档滞后） |
| **能力可达性** | ❌ **不完备** | 至少 6 类能力在 CLI/API/UI 三层中只有一层可达或完全不可达 |
| **静默正确性** | ❌ **有 2 处已确认的静默错误** | 见 P0 |
| 文档/实现一致性 | ❌ 有 5 处契约不符 | 见 P2 |

**一句话**：这不是「因子分析能力不够」，而是「因子分析能力有一批接不上、且有两处在静默出错」。
按方案自己的话说 —— **全是静默错误**，正是最危险的那一类。

### 三条最该先看的

1. **`归因分解` 100% 是错的**：`data/reports/` 下 **242/242** 份因子报告渲染的是
   `归因分解 · symbol`（按个股而非行业），旁边却写着「多空行业暴露总和 …（越接近 0 说明中性化越干净）」。

   原因是一行 `_pick()` 白名单漏了两个 key（`evaluate/__init__.py:78-82`），传进去的参数被静默丢弃。
3. **评级与稳健性（L2/L3 的核心结论）在平台内不可见**：`factor_rating` / `robustness_summary`
   只有 `lq factor audit` / `lq factor robust` 能拿到，API 与 Web 零暴露 ——
   而 `FACTOR_VALIDATION.md:67` 把「评级」列为 L2 必测项。

## 三、已确认缺陷（按危害分级）

### P0 — 静默错误：产出错误结果且不报错

#### A1. 报告「归因分解」100% 降级为按个股，且仍宣称是行业暴露

- **现象**：`data/reports/` 下 **242/242** 份报告渲染 `归因分解 · symbol`，
  表头是 `symbol / weight_long / weight_short / exposure`，逐行是 `300750.SZ`、`600519.SH` 这类**个股代码**；
  其上方提示文案却是「多空行业暴露总和 0.3467（越接近 0 说明中性化越干净）」。
- **根因**：`evaluate/report.py:250`
  ```python
  cc = cat_col or ("industry_sw1" if "industry_sw1" in df.columns else "symbol")
  ```
  当行业列缺失时**回退到 `symbol`**（语义上根本不是同一维度），而不是跳过该节或报错。
- **触发路径**：API `_evaluate_full` → `evaluate()`（`evaluate/__init__.py:78-82`）未透传 `cat_col`；
  而 `read_daily` 的列里**没有** `industry_sw1`（已实测：`['symbol','trade_date','open',...,'float_mv',...]`），
  行业只以 `cov_industry_sw1` 形式在 `factors.py:540` 之后才存在 —— 即在 `evaluate()` **之后**。
- **对照**：CLI `lq factor report` 走的是正确路径（`factor.py:509` 显式挑 `cov_industry_sw1`/`industry_sw1`）。
  **同一平台两种口径**，正是方案最担心的形态。
- **影响**：行业归因能力事实上从未交付；用户读到的是一个无意义但看起来很专业的表。

#### A2. `synthesize(method="ic_weighted")` 用的是混合池化 RankIC，与自身文档不符

- **文档**（`analysis.py:138`）：「ic_weighted 用各因子与 `fwd_ret_{h}` 的**日均 RankIC** 为权重」。
- **实现**（`analysis.py:145-161`）：`rank().over("trade_date")` 之后直接
  `pl.corr(...)` 全样本池化，**没有按日再取均值**。
- **实测差异**：同一面板下池化 RankIC `0.44608` vs 日均 RankIC `0.371854`（相对差 20%）。
  截面规模逐日变化时两者必然分叉（池化按截面大小加权，忽略日间变异）。
- **影响**：合成权重与文档口径不一致，因子合成结果不可复现地偏离预期。

### P1 — 能力不可达：引擎算得出来，用户拿不到

#### B1. `evaluate()` 静默丢弃 `group_col` / `bps_list` → 两个报告小节从未产出

- `evaluate/__init__.py:78-82` 的 `_pick(kw, ...)` 白名单只有
  `price_col/date_col/symbol_col/cat_col/universe/filter_zscore/outlier_stats/event_window`，
  **漏了 `group_col` 与 `bps_list`**（`factor_report` 两者都接受，见 `report.py:203-213`）。
- 参数被丢弃时**不报错、不告警**。
- **实测**：`data/reports/` 242 份报告中，
  「成本敏感性」**0/242**、「分组 IC」**0/242**（而「事件式分层收益」「换手率」各 235/242）。
- 连带后果：`ic_by_group`（`group_ic.py:11`）在生产代码中**唯一**调用点是
  `report.py:260`，而所有生产调用方传的 `group_col` 都是 `None`（`factor.py:511` 硬编码 `group_col=None`）
  或被丢弃 → **该能力实际不可达**。

#### B2. 评级与稳健性（L2/L3 的最终结论）在 API / Web 零暴露

- `factor_rating`（`rating.py:79`）唯一调用点：`factor.py:396`（CLI `audit`）。
- `robustness_summary` 及 5 项子检验（`robustness.py:398,168,217,266,320,378`）唯一调用点：`factor.py:475`（CLI `robust`）。
- API `factors.py` 全文无 `rating` / `robustness` 命中；Web 全文亦无。
- **后果**：平台（Web/API）里做不出「这个因子强不强、稳不稳」的结论；
  `config/factors/rating.yaml` 的阈值也没有任何查看/编辑入口。
  这与 `FACTOR_VALIDATION.md:67`（L2 判据含评级）、`SKILL.md:25-26` 的定位直接冲突。

#### B3. 中性化三视图只交付 1/3，且第三视图是纯副作用

- `neutral_views.py` 定义了三种（方案 §5.1 明确要求「页面上必须标明用的哪种」）：
  `factor_neutral`（默认）、`return_neutral_ic`、`industry_group_quantile`。
- 实际：
  - `view` 标签（`neutral_views.py:48`）**Web 从不渲染**；
  - `return_neutral_ic` ✅ Web 用（`page.tsx:704-706`）；
  - `industry_group_quantile`（`neutral_views.py:56`）**返回值被丢弃**，只置一个 `True` 标记
    （`neutral_views.py:57`），且 Web 全仓无引用 → 行业内分组分层**没有任何数字产出**。
  - 附带 bug：`factors.py:346` 调用 `_nv(...)` 时未传 `n_groups`，恒用默认 5，与用户选的 `req.n_groups` 不一致。

#### B4. 预处理配方没有任何用户面

- `orthogonalize.symmetric/gram_schmidt/pca`（`orthogonalize.py:40,72,97`）、
  `neutralize.ridge/lasso/industry_mean`、`standardize.minmax/rank`、`winsorize.quantile/three_sigma/clip`

  （`factors.py:404-410,591-595`；`submit.py:83-87`；`backtest.py:63-67`；`robustness.py:133-138`）。
- 无 API 端点、无 CLI 子命令、无前端表单。
- `pipeline.describe()`（`pipeline.py:88`）自述「给前端枚举 UI」，但**无任何调用方**。
- **后果**：方案 M2.5「配方接入 API/UI」未落地；「换配方看 IC 怎么变」这件事在平台内做不到。
