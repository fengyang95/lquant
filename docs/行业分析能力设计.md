# 行业分析能力设计与调研

> 状态：**已交付**（`src/lquant/industry` + `/api/industry` + `/industry` 前端页）。
> 本文记录「为什么这样设计」以及调研了哪些开源实现 —— 口径与取舍都写在代码注释里，
> 这里解释**决策**本身。

---

## 0. 缺口

平台原来只有 **个股分析**（`src/lquant/security`：技术 / 基本面 / 估值 / 资金 /
相对强度 / 消息面六个角度 + 综合分）。行业维度只在三个地方零散出现：

| 已有 | 形态 | 局限 |
|---|---|---|
| `/api/market/sectors` + `/sectors` 页 | 东财板块**当日快照** | 只有涨跌幅 / 主力净流入 / 涨跌家数；**无历史**，不可回看、不可比较 |
| `lquant.fundamental` | 全市场个股的**行业相对分位** | 分析对象仍是**个股**；行业只是一层分组 |
| `industry_classify` + `covariates.industry_sw1` | PIT 行业归属 | 只服务因子中性化；没有行业层面的结论 |

缺的是：**把行业当成分析对象**——「这个行业在全行业里排第几、景气度在改善还是
恶化、贵不贵、挤不挤、面宽不宽」。这正是行业轮动/行业比较要回答的问题。

## 1. 调研：开源实现与可借鉴点

调研范围：GitHub 上的 A 股量化项目 + 券商行业比较/轮动框架。判定口径：
**Polars / DuckDB / Parquet 批式 lakehouse 可实现** = ✅；需要重依赖或在线服务 = ⚠️；
需要付费数据 = ❌。

### 1.1 最值得借鉴的四个实现

| 项目 | 可借鉴内容 | 链接 |
|---|---|---|
| QuantsPlaybook「相对旋转图 RRG 行业轮动」 | RRG 三层公式、四象限判据、扩散指标（数量/市值加权）、PIT 成分展开规则 | [RRG 目录](https://github.com/hugo2046/QuantsPlaybook/tree/master/C-%E6%8B%A9%E6%97%B6%E7%B1%BB/%E7%9B%B8%E5%AF%B9%E6%97%8B%E8%BD%AC%E5%9B%BERRG%E8%A1%8C%E4%B8%9A%E8%BD%AE%E5%8A%A8) · [算法说明](https://github.com/hugo2046/QuantsPlaybook/blob/master/C-%E6%8B%A9%E6%97%B6%E7%B1%BB/%E7%9B%B8%E5%AF%B9%E6%97%8B%E8%BD%AC%E5%9B%BERRG%E8%A1%8C%E4%B8%9A%E8%BD%AE%E5%8A%A8/docs/RRG%E7%AE%97%E6%B3%95%E8%AF%B4%E6%98%8E_20260528.md) |
| QuantsPlaybook「行业指数顶部和底部信号」 | NH-NL 净新高占比公式 + 按成分股数分档的阈值体系 | [core.py](https://github.com/hugo2046/QuantsPlaybook/blob/master/C-%E6%8B%A9%E6%97%B6%E7%B1%BB/%E8%A1%8C%E4%B8%9A%E6%8C%87%E6%95%B0%E9%A1%B6%E9%83%A8%E5%92%8C%E5%BA%95%E9%83%A8%E4%BF%A1%E5%8F%B7/scr/core.py) |
| `horizon288/Level-1-industry-congestion` | 拥挤度 = 成交额占比分位 + 换手率分位的均值，高低阈值 0.8 / 0.2 | [calculator.py](https://github.com/horizon288/Level-1-industry-congestion/blob/main/calculator.py) |
| `HKUDS/Vibe-Trading` 的 `sector-rotation` skill | 景气度打分卡：盈利增速 / 盈利趋势 / 估值安全的权重与分档 | [SKILL.md](https://github.com/HKUDS/Vibe-Trading/blob/main/agent/src/skills/sector-rotation/SKILL.md) |

另外两条对**工程实现**有直接影响：

- **RRG 的预热长度是硬约束**：`RS-Ratio = mean₂₀(100 × RS / shift(RS, 220))`、
  `RS-Momentum = mean₂₀(100 × RS-Ratio / shift(RS-Ratio, 60))`，合计
  `220 + 60 + 2×20 = 320` 个交易日。这直接决定了行情回看窗口必须 ≥ 该长度
  （实现取 720 自然日 ≈ 490 个交易日）。**不能缩窗口凑一个数出来** ——
  那会让不同标的算的不是同一个指标。
- **PIT 成分展开规则**：区间语义是半开区间 `[in_date, out_date)`，同一
  `(trade_date, code)` 保留一条（排序键 `in_date DESC → industry_code ASC`），
  且要保留退市股历史归属。lquant 的 `industry_classify.std_date` 是「生效日」
  语义，用 `join_asof(strategy="backward", by="symbol")` 一次向量化即可等价实现。

### 1.2 免费数据源：现状与推荐

调研确认了**免费**就能拿到行业级必要字段的接口（当前仓库未接入，属后续路线）：

| 能力 | 免费来源 | 接口 | PIT |
|---|---|---|---|
| 申万个股归属（含变动史） | akshare（申万官网） | `ak.stock_industry_clf_hist_sw()` → `symbol, start_date, industry_code` | ✅ 有计入日期 |
| 申万个股归属（含调出） | tushare | `pro.index_member_all()` → `in_date / out_date` | ✅ 最完整（2000 积分） |
| **申万行业指数日线** | akshare（申万官网） | `ak.index_hist_sw(symbol, period)` | — |
| **申万行业 PE/PB/换手/成交额占比** | akshare（申万官网） | `ak.index_analysis_daily_sw(symbol="一级行业", ...)` | — |
| 行业资金流 | akshare（东财） | `ak.stock_sector_fund_flow_rank / _hist` | — |
| 分析师一致预期 | — | — | ❌ 付费，不可得 |
| 自由流通市值 | — | — | ❌ 免费源只有流通市值 |

**两条硬缺口必须在产品里说清楚**（本实现已在报告口径里声明）：

1. **分析师一致预期不可得** → 「景气**预期**」框架（广发证券）无法复现。
   本实现退化为「**已实现**财报景气度」：营收/净利同比 + ROE + 环比动能。
   失去的是前瞻性，保住的是可复现性。
2. **自由流通市值不可得** → 扩散指标只能用**流通市值**或**等权**加权。
   本实现用等权并显式声明口径，避免出现「看起来是研报口径、其实不是」的假精确。

调研明确标记为**不实用**、本实现刻意不做的：ETF 全持仓/PCF 暴露矩阵
（免费源只有季报前十大重仓，行和 ≈ 0.5，行业约束形同虚设）、
依赖 `qlib` 表达式引擎 / `talib` / `alphalens` / `torch` 的实现（公式可直接用
Polars 重写）、依赖 JS 取 cookie 的接口、以及 `rqdatac` 等付费 API。

## 2. 设计

### 2.1 与个股分析的关系：共享契约，独立角度

两者产出的是**同一种东西**：一份「0–100 分 + 分角度可解释指标」的报告。
所以通用部分被抽到 `lquant/core/report.py`，**只有一份实现**：

| 共享（`core/report.py`） | 各自定义 |
|---|---|
| `NEUTRAL` / `to_score` / `stance_of` / `signal_of` | 角度注册表与权重 |
| `metric` / `percentile_rank` / `safe_float` / `tanh_norm` / `pct_text` | 分级措辞（偏多/偏空 vs 强势/弱势） |
| `num` / `json_safe`（非法 JSON 会让前端白屏） | 角度计算（`angles.py`） |
| `composite_scores`（权重归一化 + 双覆盖度） | 结论生成（`score.py`） |

前端同理：`web/src/lib/report.ts` + `web/src/components/ReportView.tsx` 是共用层，
`security.ts` / `industry.ts` 只补自己的字段。**同一份契约在两处渲染出不同样式，
会让读者误以为分数口径不一样。**

> 抽取消原则：**两次就抽**。原来这些原语只在 `security/contract.py`，行业分析
> 一出现就变成两个调用方 —— 复制粘贴等于埋第二套口径。

### 2.2 五个角度（非零权重和为 1.0）

| id | 名称 | 权重 | 数据来源 | 核心信号 |
|---|---|---|---|---|
| `trend` | 趋势与轮动 | 0.28 | 行业合成指数 + 基准 | 20/60/120 日收益、相对基准超额、**全行业相对强度分位**、均线偏离、**RRG 四象限** |
| `prosperity` | 景气度 | 0.24 | `financial_pit`（PIT） | 营收/净利同比、ROE 的**中位数水平** + **相对全市场超额** + **环比动能** |
| `valuation` | 估值 | 0.18 | `daily_basic` | PE/PB 中位数的**自身历史分位** + **全市场横向分位** |
| `capital` | 资金与拥挤度 | 0.16 | `money_flow` + 日线成交额 | 主力净流入（绝对 + 相对净额比 + 占全市场份额）、**拥挤度**（成交额占比分位与换手率分位的均值，反向计分） |
| `breadth` | 宽度与情绪 | 0.14 | 成员日线 + `limit_up_pool` | 上涨家数占比、**NH-NL 净新高占比**、创 60 日新高占比、分化度、涨停天数 |

权重依据：行业轮动（sector momentum）是行业分析最主要的可交易信号且数据最全，
故 `trend` 最高；`prosperity` 受 PIT 财务披露节奏限制（季度 + 覆盖度），不盖过趋势；
其余三个作辅助确认。

### 2.3 行业指数：自己合成，口径写清楚

`行业日收益 = 成分股日收益的等权平均`，`行业指数 = Π(1 + 日收益)`。

**为什么不用申万官方行业指数**：需要新数据源（见 §1.2），而等权合成完全落在
已有数据源内、PIT 安全、可复现、不被个别巨头市值碾压。代价是与行情软件的行业
指数涨跌幅有差异 —— 这一点在 **API 响应、报告 `disclaimer`、前端概览面板**
三处都显式声明，不含糊过去。

同时输出**中位收益**作为对照：等权与中位明显背离 = 行业内部分化严重（少数大票
拉动），这个差异本身就是信息。

### 2.4 PIT（无未来函数）的三条边界

1. **行业归属**：`industry_classify.std_date <= trade_date`，用
   `join_asof(strategy="backward", by="symbol")` 向量化解析。窗口内发生的行业
   变更会被逐日正确处理 —— 用今天的分类回溯整段历史是前视偏差，也会让同一个
   行业的「历史」每次分类调整都被重写。
2. **财务**：`pub_date <= asof`，且取**最近两期**（最新的定水平、上一期的定环比动能）。
3. **行情 / 估值 / 资金流**：`trade_date <= asof`；`asof` 缺省取**湖内最新交易日**
   而不是自然日（同步滞后于自然日时，用自然日会把「还没同步」误判成「数据缺失」）。

### 2.5 降级纪律：只报告算得出来的东西

沿用个股分析的一条纪律：**任何一个角度取不到数 → `available=false` + `hint`**，
绝不用「中性 50 分」把空缺填平。样本不足就不出分位（返回 `None`），
RRG 预热不足就不出象限，只有 1 家公司的行业中位数不给分。

覆盖度分两层上报，读者必须能分辨「5 个角度都算出来了」和「只有 2 个角度有数据」
给出的 70 分不是一回事：

- `angle_coverage`：有分的角度占**应有权重**的比例（分析面覆盖度）
- `data_coverage`：有分角度的**内部数据覆盖度**加权平均（数据面覆盖度）

## 3. 交付物

### 3.1 后端

```
src/lquant/core/report.py        报告契约通用原语（新增，security 改为 re-export）
src/lquant/industry/
  __init__.py                    对外入口
  contract.py                    角度注册表 + 分级措辞（强势/弱势）
  loader.py                      PIT 取数 + 全市场行业面板（带 TTL 缓存）
  angles.py                      五个角度 + RRG + NH-NL（纯函数）
  score.py                       综合分 + 结论（复用 composite_scores）
  service.py                     analyze_industry / industry_rotation / list_industry_names
src/lquant/server/api/industry.py  /api/industry/* 路由
```

`_build_universe` 会一次性读取全市场日线并做 PIT 归属 join，两个端点共用同一份
带 TTL 缓存的面板（默认 720 自然日窗口）。

### 3.2 API

| 端点 | 用途 |
|---|---|
| `GET /api/industry/angles` | 角度注册表（前端图例/文档） |
| `GET /api/industry/list?std=&asof=` | 行业清单（代码/名称/成员数/最近收益） |
| `GET /api/industry/rotation?window=&std=&asof=` | 全行业轮动榜（含排名与分位） |
| `GET /api/industry/{identifier}/analysis?std=&asof=` | 单行业多角度报告（代码或中文名） |

`/rotation`、`/list`、`/angles` 是静态路由，注册在 `/{identifier}/analysis` 之前，
不会被动态路由吞掉（有测试守着）。

### 3.3 前端

- `/industry`：行业轮动榜（窗口切换 20/60/120 日、排名、区间收益条、成员数、
  成交额、PE 中位数、全行业分位），每行链到详情。
- `/industry/[identifier]`：多角度报告 + 行业概览（成员数 / 当日等权涨跌 /
  全行业排名 / 近 20 日涨幅最大的成员）。
- 侧栏「市场」组新增「行业分析」入口。
- 展示层与个股分析共用 `ReportView`。

### 3.4 其他

- MCP 工具 `get_industry_rotation` / `get_industry_analysis`（供「问 AI」调用）。
- 演示数据补齐 `daily_basic`（估值）、`financial_pit`（PIT 财务）与 `index_daily`
  （基准）：缺了它们，演示环境的估值/景气度/相对强度角度会**安静地**变成
  `available=false`，从页面上分不出是「没数据」还是「代码坏了」。

## 5. 后续路线（本次**未**做，写明原因）

| 项 | 价值 | 为什么没做 |
|---|---|---|
| 接入申万官方行业指数日线（`ak.index_hist_sw` / `index_analysis_daily_sw`） | 与研报/行情软件口径对齐；估值分位不再依赖成分股聚合 | 需要新增一个数据源 provider 与依赖，是独立的一步工作；当前等权合成口径已可用且已声明 |
| 行业分类变动史的数据源（`stock_industry_clf_hist_sw` / `index_member_all`） | 更完整的 PIT 归属（当前依赖已有 `industry_classify` 的同步质量） | 同上 |
| 自由流通市值加权扩散指标 | 对齐研报口径 | 免费源拿不到自由流通市值（§1.2） |
| 行业资金流（`stock_sector_fund_flow_hist`） | 行业层面资金流不依赖个股聚合 | 同上，属数据源扩展 |
| 行业成分股集中度 HHI / 产业链传导 | 行业比较的补充维度 | 价值明确但优先级低于上述数据源；现有宽度与分化度已覆盖基本需求 |
| 基于行业报告的轮动回测（RRG Top-N + 扩散过滤） | 把分析变成策略 | 属于 `backtest` 侧的新策略，与本次「能力补齐」是两件事 |
